# EVA F1.3 — Agent & Integration checkpoint

Based on F1.2. No production, GitHub or Netlify deployment.

## Changes
- Extracted server-only EVA Interpreter/Maya instructions into `netlify/functions/scenarios/eva-agent-instructions.js`.
- `interpret()` supports 0..4 target schema (PWR0), general visual inventory, multiple ordered actions, and explicit ambiguity via null targets.
- `executeTurn()` validates an initial-visibility snapshot so a chained command cannot manipulate a newly revealed physical layer. No queued instructions.
- Maya input contains only physical observation text and explicit Ground terminology, never result codes, internal World fields, Ground telemetry or remainingSeconds.
- The returned UI `action` is deterministic WORLD feedback; model-generated physical stage directions are discarded.
- `OBSERVE_ACT` no longer silently rotates/tests the gear; `TEST_ACT` remains the actual rotation test.
- `learnedVocabulary` persists explicit technical explanations without revealing objects.
- Existing `/chat` request/response shape and encrypted state token preserved; frontend consumes deterministic `action` unchanged.

## Tests
- 21/21 deterministic tests pass (F1.1 7 + F1.2 7 + F1.3 7).
- Node syntax checks pass. No live OpenAI or Netlify UAT test performed.

## Limitations / required validation
- Live model interpretation and Maya dialogue need UAT playtesting, including FR/EN natural-language ambiguity and agent hallucination resistance.
- Legacy `TEST_LATCH` remains available as a distinct mechanism test; F2 can refine.
- Existing V1 EVA state tokens are rejected by World V2. Start a new EVA game.
- F2 timed actions, server-authoritative oxygen, persistence and stress remain out of scope.
